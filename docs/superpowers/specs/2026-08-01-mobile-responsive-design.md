# Мобильная адаптация: навигация + защитные правки для узких экранов

**Дата:** 2026-08-01
**Репозиторий:** `DiscordForFemka-Frontend` (изменения только на фронте)
**Ветка:** `feat/mobile-responsive`

## Проблема

Сайт (Vite + React + TypeScript + Tailwind + shadcn/ui) практически не
адаптирован под мобильные экраны:

- В `Header.tsx:76` вся основная навигация (`Главная`, `Сцены`, `Рейтинг`,
  `Архив`, `Лобби`, `Приглашения`, `Профиль`, `Админка`) объявлена как
  `hidden gap-6 text-sm sm:flex` — **на экранах < 640px пункты меню просто
  исчезают без какой-либо замены**. Разделы сайта становятся недоступны с
  телефона.
- `AdminLayout.tsx` использует `grid md:grid-cols-[200px_1fr]` — на мобильном
  левое меню из 9 разделов (MMR, Сезоны, Турниры, Матчи, Игроки, Команды,
  Аудит, Боты, Лобби) схлопывается в сплошной вертикальный список **над**
  контентом, из-за чего пользователь скроллит длинный список меню, прежде чем
  увидит сам раздел.
- Ряд `<table>` в админ-страницах не гарантированно обёрнут в
  `overflow-x-auto` и может ломать вёрстку на узких экранах.

Целевая минимальная ширина — **375px** (iPhone SE/12/13 mini и похожие).
Брейкпоинты — стандартные Tailwind (`sm`/`md`/…), кастомные не добавляем.

## Ключевые факты (из анализа кода)

- Стек: Vite + React 18 + TypeScript + React Router v6 + TanStack Query,
  Tailwind CSS 3 + shadcn/ui (Radix + `class-variance-authority` +
  `cn()` из `src/lib/utils.ts`). Viewport meta-тег уже есть
  (`index.html:6`).
- Самые «тяжёлые» с виду куски вёрстки **уже адаптивны**, доработка не
  нужна:
  - `TournamentDetailsPage.tsx` — сетка плей-офф (`PlayoffBracket`,
    строки 783/787) обёрнута в `max-h-[70vh] overflow-auto`, колонки
    раундов — `w-max min-w-full`. Горизонтальный скролл уже работает.
  - `GroupStageBlock.tsx:100` — таблица группы уже в `overflow-x-auto`.
  - `LiveStatsCard.tsx:108` и `ResultStatsCard.tsx:132` (статистика
    матча, самые широкие fixed-px grid'ы, ~500–700px) — уже в
    `overflow-x-auto`.
  - `LobbiesPage.tsx` — фильтры (`sm:grid-cols-2 lg:grid-cols-4`,
    строка 213) и карточки лобби уже адаптивны.
- Реально проблемные места — только навигация (шапка, админ-сайдбар) и
  вероятно необёрнутые `<table>` в админке.
- `MatchDetailsPage.tsx:676` — шапка счёта `grid-cols-[1fr_auto_1fr]` без
  `sm:`-варианта, имена команд через `truncate`. Требует точечной проверки
  на 375px, но структурных изменений заранее не планируем — только если
  проверка покажет поломку.
- `LeaderboardPage.tsx` (`LeaderboardRow`, строка 172) — уже
  `flex flex-wrap ... sm:flex-nowrap`, требует точечной проверки на 375px.
- Пользователь ограничил объём этого захода: критичная навигация +
  приоритетные страницы (Главная, Сцены, Турнир, Лобби, Матч, Лидерборд) +
  вся админка. Профиль, страница игрока и страницы команд — вне рамок.

## Решение

Frontend-only, без изменений API/бэкенда.

### 1. Мобильное меню в шапке (`Header.tsx`)

- На `< sm` вместо скрытого `<nav>` показываем кнопку-гамбургер (иконка из
  `lucide-react`, уже используется в проекте) рядом с лого.
- По клику под шапкой (`<header>`) раскрывается панель на всю ширину со
  списком тех же ссылок, что сейчас в desktop `<nav>` — с той же логикой
  видимости по ролям/авторизации (`isAuthenticated`, `isStaff`,
  `pendingInviteCount`). Не оверлей/portal, не сдвигает контент под собой
  (панель — часть потока документа, контент ниже уезжает вниз, пока меню
  открыто).
- Состояние открытия — локальный `useState<boolean>` в `Header`. Закрытие
  по клику на ссылку (переход) и по повторному клику на гамбургер.
- На `>= sm` — без изменений, текущий `<nav>` остаётся как есть.
- Правый блок шапки (тема, колокольчик, аватар/логин) не переносится в
  меню — остаётся видимым в шапке на всех ширинах, как сейчас.

### 2. Мобильное меню в админке (`AdminLayout.tsx`)

- На `< md` вместо текущего схлопывания в вертикальный список рендерим
  список из 9 разделов как горизontal-scroll полосу «пилюль» (`flex gap-2
  overflow-x-auto`, каждый пункт — `Link` с закруглённым фоном, активный
  раздел подсвечен), сразу над контентом.
- На `>= md` — без изменений, текущий левый сайдбар-список остаётся.
- Реализация — два варианта разметки одного и того же списка ссылок
  (переиспользуем текущий источник пунктов меню), переключаемые классами
  `md:hidden` / `hidden md:block`, без дублирования логики активного
  пункта.

### 3. Защитная обёртка для таблиц админки

Пройтись по всем `<table>` в:
`AdminPlayersPage.tsx`, `AdminTournamentsPage.tsx`, `AdminMatchesPage.tsx`,
`AdminTeamsPage.tsx`, `AdminMmrPage.tsx`, `AdminSeasonsPage.tsx`,
`AdminBotsPage.tsx`, `AdminAuditPage.tsx` — и убедиться, что каждая обёрнута
в контейнер с `overflow-x-auto`. Где обёртки нет — добавить. Изменение
только в разметке, без изменения логики/данных.

### 4. Точечная проверка приоритетных страниц на 375px

Без заранее спланированных структурных изменений — только визуальная
проверка в браузере на ширине 375px, фиксы по месту, если что-то
переполняется/наезжает:

- Главная, Сцены (`ScenesPage` + `/scenes/:slug`), `TournamentDetailsPage`
  (вкладки, заголовок, обзор — сетка/группы уже скроллятся).
- `LobbiesPage` — верификация (уже адаптивна).
- `MatchDetailsPage` — шапка счёта `grid-cols-[1fr_auto_1fr]`, не
  ломаются ли имена команд/счёт.
- `LeaderboardPage` — `LeaderboardRow` на 5 колонок, корректность переноса
  при `flex-wrap`.

## Проверка

- `npm run build` — типы и сборка проходят без ошибок.
- Ручной прогон в браузере на ширине 375px (плюс контрольная проверка
  desktop-раскладки, чтобы не было регрессий):
  - шапка: гамбургер открывает/закрывает меню, все пункты кликабельны и
    учитывают роль/авторизацию так же, как сейчас на desktop;
  - админка: горизонтальная полоса разделов скроллится, активный раздел
    подсвечен, переход между разделами работает; на `>= md` сайдбар как
    раньше;
  - все таблицы в перечисленных админ-страницах скроллятся по горизontали,
    не ломая остальную страницу;
  - приоритетные страницы из п.4 визуально не ломаются на 375px.

## Вне рамок (YAGNI)

- Профиль, страница игрока, страницы команд — не трогаем в этом заходе.
- Не переписываем таблицы админки в карточки — оставляем горизонтальный
  скролл.
- Не добавляем нижний таб-бар и не трогаем турнирную сетку/групповую
  стадию/статистику матча — они уже скроллятся горизонтально.
- Не добавляем кастомные Tailwind-брейкпоинты.
- Не меняем backend/API.
